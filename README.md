# 智研引擎 Demo

## 从 GitHub 获取并运行

本仓库提供源码、启动脚本、操作指南与合成初始展示数据。运行环境已在 Windows x64、Python 3.12.4、Node.js 24.14.1 验证；首次安装依赖需要联网。

```powershell
git clone https://github.com/lvjunchi/zhiyan-demo.git
cd zhiyan-demo
python -m pip install -r backend/requirements-dev.txt
cd frontend
npm ci
cd ..
.\Start-Demo.cmd
```

浏览器打开 `http://127.0.0.1:5181/`。首次启动从合成初始展示源创建本地工作副本；后续启动保留已保存进度。完整操作只看 [系统操作与演示指南](docs/DEMO_GUIDE.md)。退出时在启动窗口输入 `stop` 并回车，等待备份完成。

个人工作数据库、历史备份、浏览器草稿、依赖目录、测试截图/测试库、交付压缩包和参考原件不随源码上传；历史测试报告仅保留摘要；截图、命令输出和关键JSON证据保留本地，历次pytest临时工作目录已按2026-10-29清理清单删除，可由测试重新生成。`参考文档/` 为未公开原件，后续开发涉及这些依据时需由材料提供方另行提供。本仓库用于本地单用户合成演示，上传 GitHub 不会自动部署为在线系统。

## 启动与发送

1. 完整解压项目文件夹，保留 `data/` 中的工作副本、活动指针、恢复目录和备份。
2. 已有依赖时双击 `Start-Demo.cmd`，打开 [本地系统](http://127.0.0.1:5181/)。保持启动窗口运行。
3. 退出时输入 `stop` 回车，系统先备份后停止自己启动的服务。

老师的Windows电脑需安装Python、Node.js及项目依赖。验证环境为Python 3.12.4、Node.js 24.14.1；仅装Python/Node不等于依赖齐全。首次安装可联网执行：

```powershell
python -m pip install -r backend/requirements-dev.txt
cd frontend
npm ci
cd ..
```

依赖及浏览器预装后，受控主线可以断网运行。无需模型密钥；不承诺空白电脑离线安装。`.venv` 不应作为跨电脑可用环境；`node_modules` 可随同发送但较大，兼容性以老师电脑为准。发送时使用已校验的精简交付包，不要再次压缩整个开发目录；当前源码和操作说明以GitHub仓库为准，2026-10-27的ZIP是当日快照。重新打包业务进度应使用SQLite一致性快照，不能只发 `data/demo.db` 或复制正在写入的数据库。

启动故障先看窗口提示和 `.runtime/` 中的前后端日志。不覆盖已有数据、不自动重置、不强行终止占用端口的其他程序。[详细说明](老师使用与演示说明.txt)。

## 从文件开始演示

当前打开系统先展示一套完整初始场景：由 `演示导入文件/01_重型变速器技术协议_V1.docx` 真实导入13条需求，再加载独立的合成澄清、选型、设计、试验、样件、沟通和进度记录。协同图显示48/52/56小时响应、高风险及触发原因；不是从协议推断出的沟通历史。材料包保留待处理的协同风险，不自动批准。

正式重新演示：系统设置 → 重新开始项目 → 预览并备份清空 → 重新载入空白项目 → 导入流程演示版Word或PDF，生成19条待审核需求。清空后旧设计、试验、样件及协同记录一起移除，重启不会自动补回；不要向现有展示项目直接叠加同一份新协议来代替清空。

`data/initial-showcase/initial.db` 是预置场景源，`initial-backup.json` 可在系统设置中显式恢复（整库恢复，先备份并核对范围）。启动器只在尚无工作副本时复制完整的预置源，已有工作副本/恢复指针始终保留；缺少完整预置源时沿用 `data/demo.db`。

首次完整操作推荐[流程演示版协议](演示导入文件/流程演示/01_流程演示协议_V1.docx)或[同文PDF](演示导入文件/流程演示/01_流程演示协议_V1.pdf)，每次只选一份：19条草稿、0条待澄清，最高档和耐久合成判据已明确。需求仍须人工确认，配套评分/协同可在界面填入合成样例，保存和确认各自提交。[原综合演示资料](演示导入文件/综合演示/README.txt)保留19条草稿、2条待澄清，供澄清与变更演练；编号映射为高级可选项。

主线：清空前备份 → 协议导入与正文核对 → 需求审核与澄清 → 型谱/变型/零件选择及确认 → 设计评审/DFMEA → 试验方案/用例/执行 → 样件检验 → 一致性与协同风险处置 → 材料包检查、导出及审批。

待核对文件支持当前浏览器草稿保留及列表“继续核对”，切换模块/刷新可恢复正文、来源字段、映射和原件。旧记录或无本地草稿时按提示重选同一文件，核对校验值后沿用原记录。未归档草稿不包含在业务JSON备份中，发送老师前请完成归档/解析；取消、成功解析、清空/恢复会清理相关浏览器草稿。

清空只在“系统设置 → 数据管理 → 重新开始项目”显式执行，须预览、输入项目编号；清空原件及关联成果，保留项目入口、基础库、其他项目、编号计数和配置。备份落盘并回读验证后切换独立副本，原库保留。

需求一键确认先预览明确范围，不自动跳过错误或确认驳回项。修订需求和用例均建立新版本，需另行审核。零件在“型谱选型与变型 → 零件型号选择”比选；24型号为合成候选，图示和匹配包络不代表制造认证。

试验审核、有效性、执行与符合性分开；“修订用例”可补条件和判据，静扭冻结门槛只读。样件结果内“记录复检”建立新版本。协同每个议题可登记参与方计划/实际/交付版本，更新后必须重算指标。JSON样例用于填值和隔离排练，并非通用的一键导入格式。

[完整操作与变更演练](docs/DEMO_GUIDE.md)。原简版Word仍保留，解析13条，不能与综合版19条的口径混用。

## 能力边界

- Word主要支持 `.docx`；PDF须有可提取文字，老版 `.doc` 与扫描PDF需外部转换/OCR。
- 文件抽取、规则解析、引用、版本、审核、失效、保存和导出真实运行；未接入行业模型API、CAD自动判断、检测设备、生产系统或真实权限认证。
- 三方完整派发、供应商/批次归集等▲项目不在P0。协同进度及样件实测来自人工/合成记录。
- 当前5条固定验证范围不包含所有新增要求，范围与覆盖分母在界面明确显示；20℃单点不能证明整个温度区间。
- JSON是维护备份，评审材料包是带快照与校验值的ZIP，两者用途不同。旧结构备份不直接恢复到新结构；保留原文件并核对版本。
- 本轮受控主线已验证，长期压力、任意复杂文档与完整生产级混沌尚未验收；不据此签署AC-01—AC-21任意场景全部通过。
