# UI-PACKAGE-02 评审材料按钮越界修复

关联：用户本轮截图、O13、AC-20/21 的展示范围。纯 CSS 修复，不改变材料包状态、审核或检查规则。

## 原因与变更

此前用视口高度 1000px 切换材料卡片的紧凑样式。1920×1001 时底部卡片实际只有 180.67px 高，却切回完整内容，按钮越过卡片底边 10.92px。前轮只检查常见尺寸，遗漏这个临界区间；前轮三尺寸通过不能证明此区间没有问题。

改为桌面底部行建立尺寸查询容器，按实际可用高度选择完整、紧凑和矮屏布局（206px、165px），统一调整图标、数字、间距和按钮尺寸。平板和手机采用自然高度，不对自动高度容器做尺寸约束。保留按钮完整区域和底部内边距，没有用隐藏溢出来掩盖按钮。

## RED → GREEN → REFACTOR

在 frontend 运行：

`npx playwright test --config playwright.cockpit.config.ts package-boundary.spec.ts`

RED 退出 1：`compact 1920x1001: action preserves card padding`，期望底部距离至少 14.5px，实际 -10.921875px。见 red.txt。

初步改为容器查询后同一测试退出 0，见 green.txt。随后细化中等高度字号与紧凑层级，补查新布局边界前后，最终运行：

`npx playwright test --config playwright.cockpit.config.ts package-boundary.spec.ts homepage.spec.ts`

3 项通过、退出 0，见 refactor.txt。新增用例覆盖 19 个尺寸 × 2 种密度，共 38 组布局断言，包括原 1000/1001px 临界区间、两个新布局切换点、1366×768、平板和手机。检查按钮保留实际内边距、整卡及检查摘要均无内部裁切，独立测试库前后业务 SHA 相同。原首页测试继续验证桌面同屏、其他卡片布局、导航和业务模块。

`npm run lint`、`npm run build` 均退出 0；最终构建 102 模块成功。本轮只改 CSS 和浏览器回归，没有重跑后端、组件全量或覆盖率，无新增覆盖排除，不引用此前结果作为本轮测试。
