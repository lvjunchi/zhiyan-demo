# IMPORT-RESUME-01 待核对草稿恢复

关联本轮真实操作断点、O1、AC-02/04/18/20/21。原后端提取记录仅保留文件名、哈希和状态，正文/原件/核对字段只在ParsingPanel临时状态，切模块卸载后丢失；列表只有取消操作。

## 实现与边界

- 新增按项目UUID和处理记录UUID隔离的浏览器IndexedDB核对草稿，保留正文、文档编号/类型/版本、映射及原件。原件独立存储，同一草稿后续文字修改不反复写原件；支持超过localStorage容量的附件。存储操作排队，删除排在旧写入之后，避免取消后旧异步写入复活。
- 提取完成直接保存草稿，不依赖组件仍挂载；后续表单修改保存。启动时先核对后端当前处理记录/归档状态，失效、已取消或已完成记录不被恢复。查看其他已归档结果不改变当前草稿的源绑定。手工表单转文件草稿时消费旧手工草稿，成功提交后不残留旧表单。
- 待核对行增加主色“继续核对”，取消按钮保留。继续可恢复指定草稿，切模块和浏览器刷新可恢复最近有效草稿，项目之间不混用。
- 旧记录或当前浏览器无缓存时显示“选择原文件恢复核对”。用既有无状态提取接口核对原文件名与SHA-256，再沿用旧import_id；不同内容即使同名也拒绝，不新增处理尝试。未保存过的旧手工修改无法恢复，编号/版本/映射需重新核对。
- 归档后解析失败保留归档引用和映射，可继续重试，不重复创建来源。取消、成功解析清理对应草稿；显式项目清空只清理本项目，整库恢复清理全部旧浏览器草稿。业务操作成功但本地清理失败明确区分提示。
- 草稿仅当前浏览器，不进入业务JSON备份，换电脑/清除浏览器数据可能需要原件重选；存储读取、配额/写入失败不冒充已保存。后端仍是处理状态、归档和审核唯一权威，无数据库迁移或新增API。生产依赖不增加，fake-indexeddb@6.2.6仅作开发测试且锁定。
